# ADR-0001: Engine, language and pinned versions

- Status: Accepted. TargetFramework: **net10.0** (proven by a CI export on 2026-11-21, see below).
- Date: 2026-11-21

## Context
- The game is a 3D boxing game built under a hard rule: **no external assets**. Every mesh, texture,
  shader and sound is generated by code.
- **Cost rule:** every engine-related component must be free, with no paid tiers, trials or usage caps.
- The client is an experienced C# developer who is new to game engines.
- Most of the work is done by AI agents, so the toolchain must give fast, strict, machine-readable
  feedback (compiler errors, unit tests, headless runs).

## Decision
Use **Godot 4.7.2 (.NET build) with C#**.

### Why Godot .NET over Unity
- Godot is MIT-licensed and free for every use, with no runtime fee, seat licence or revenue threshold.
  Unity's licensing has paid tiers and terms that can change.
- Godot's scene and resource files are plain text, so agents can read, diff and review them in git.
- Godot runs headless from the command line (build checks, smoke runs, exports in CI) with no licence
  activation step.
- Built-in procedural tools fit the no-assets rule: primitive meshes, CSG, ArrayMesh/SurfaceTool,
  NoiseTexture2D, GradientTexture2D and AudioStreamGenerator.

### Why C# over GDScript
- The client already knows C#, so they can read any code they want to inspect.
- Static types plus `TreatWarningsAsErrors` and `Nullable=enable` make the compiler a strict oracle, which
  catches invented or obsolete engine APIs (CS0618/CS0612) before a human sees them.
- Pure game logic can live in a plain .NET library (`Boxing.Core`, no Godot reference) tested with xUnit
  and `dotnet test`. That is fast, runs anywhere, and is standard tooling.

### TargetFramework decision (Stage 2, 2026-11-21)
The rule: stay on `net8.0`, the Godot 4.7 default, unless the official Godot 4.7 docs **and** a successful
local build **and** export prove `net10.0` works.

Evidence collected:
| Check | net8.0 | net10.0 |
|---|---|---|
| Godot 4.7 docs, C# basics page: ".NET 8 or later" (Android export needs .NET 9+) | ✅ | ✅ allowed |
| GodotSharp 4.7.2 package targets | net8.0 | net8.0 (usable from net10.0) |
| `dotnet build Boxing.sln -warnaserror` | ✅ 0 warnings | ✅ 0 warnings |
| `dotnet test tests/Core.Tests` | ✅ 3/3 | ✅ 3/3 |
| `godot --headless --path . --build-solutions --quit` | ✅ | ✅ |
| Headless smoke (Godot loads the assembly; runtimeconfig tfm checked) | ✅ PASS | ✅ PASS (runtimeconfig `net10.0`) |
| `--export-release "Windows Desktop"` (CI, ubuntu-24.04, templates 4.7.2) | ✅ run 44948729756 | ✅ run 44953758554 |
| Exported zip runtime | .NET 8 (self-contained) | `Microsoft.NETCore.App.Runtime.win-x64` **10.0.15**, runtimeconfig tfm `net10.0`, 192 files in `data_Boxing_windows_x86_64/` |

The setup machine has no export templates, so CI proved the export for both frameworks (2026-11-21).

**Decision:** all three projects target **`net10.0`**. The rule's three conditions are met: the Godot 4.7
docs allow ".NET 8 or later", the local build/tests/smoke pass, and the CI Windows export passes. .NET 8
support ended on 2026-11-10. .NET 10 is the current LTS release, supported until about November 2028.

**If a future Godot or .NET update breaks net10.0:** go back to `net8.0` in the three project files (a
3-line change) and record why in a new ADR.

Note: Godot.NET.Sdk 4.7.2 also ships an opt-in preview binding ("Godot .NET", `EnableGodotDotNetPreview`).
We use the default, stable GodotSharp bindings.

## Consequences
- Agents must use Godot 4.7 APIs only. They check against the exact-version GodotSharp.xml or
  docs.godotengine.org/en/4.7, and CI greps for Godot 3 names.
- Upgrading Godot is a deliberate change: update global.json, the SDK version in project files, SETUP.md,
  CI and this ADR (or a new one) together.
- Exporting needs the matching 4.7.2 .NET export templates installed (locally and in CI).
